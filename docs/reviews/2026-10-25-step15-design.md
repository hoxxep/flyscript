# Step 15: suspending code as state machines — the implementation

The roadmap's step 15 says what is wanted: a parked task holds what a Rust future holds, and fibers are gone from the native runtime. The review of 2026-10-24 (`2026-10-24-panics-and-state-machines.md`) settled the shape: frames of direct calls nest in their caller's, frames of indirect and recursive calls come from a task's frame arena, and a continuation that outlives its `handle`, or a `Gen`, owns a detached arena. This document says how the compiler and the runtime do it, and in what order, each phase leaving every test green on every back end.

## One protocol for every suspension

Today three things suspend, each its own way: a task asks the scheduler by switching to its fiber (`ask` in runtime.c); a body under a handler that is not direct performs by switching to the handler's fiber; a producer under `generate` yields by switching back to `next()`. After this step all three are one thing: **a call returns with the task's context marked pending**, and everything between the code that suspended and the code that takes the suspension returns too, each function having saved where it was.

- `fly_pending` is a field of the task's context, as `fly_unwinding` is. A function that can suspend checks it after each call that can, exactly where it checks `fly_unwinding` today.
- What the suspension is for is in the context too: a request to the scheduler (what `ask` passes today), an operation performed for handler `h`, or an item yielded to a `Gen`. Whoever takes it clears `fly_pending`.
- Resuming calls the same functions again, from the root of what suspended: each finds where it stopped in its frame and goes on.

## Which functions are state machines

A C function the back end emits — a function instance, a closure, or code made apart: a `handle`'s body or arms, a loop's body over a generator, a `defer` — is a **machine** if it contains a suspension site, a statement that may leave it pending:

- a call whose IR `suspends` flag is set (in phase B, when `Io` suspends) and every call of a machine, directly or through a function value whose type can suspend;
- `Perform`, `Resume`, and a `Yield` that goes to a sink that may suspend;
- a `handle` that is not direct, whose body or arms may leave pending what the `handle` does not take.

Everything else is compiled as it is today, and runs on the worker's own stack wherever it is called from. A function that cannot suspend costs nothing new.

## Frames

A machine `F` has a frame, a C struct (and the same layout in LLVM):

```c
typedef struct F_frame {
  uint32_t state;              // 0 before it starts; otherwise the site it stopped at
  T3 v3; T7 v7; ...            // the locals live across a site
  union {                      // the frame of the call it is in, at one site at a time
    G_frame s1; H_frame s2; void* s4;
  } sub;
} F_frame;
```

- **Which locals.** A local is in the frame if it is in scope at some site and the code may read it after that site: a use after the site in the local's scope (anywhere in a loop around the site, which may run again), or a cleanup of its block — a drop, an arena, a `defer`'s flag — which runs as the block is left. The rest stay C locals, dead across every site. A first version keeps one field per such local; overlapping fields whose lifetimes are disjoint (a union per group of sites) comes after, measured.
- **Nested frames.** A direct call of a machine that is not in the caller's strongly connected component nests the callee's frame in the caller's `sub` union. A task whose calls are all of that kind has one frame of a size the C compiler knows.
- **Arena frames.** A call through a function value, or within a cycle of machines, takes its callee's frame from the task's frame arena (`fly_frame_push(size)`, popped as the call ends), and keeps the pointer in `sub`. A function value whose type can suspend carries its frame size. Arena chunks never move, so a borrow into a frame stays good while it is suspended.
- **Detached frames.** A `handle` that is not direct, and `generate`, own their body's frame: a heap frame, as a `handle`'s is today, with a frame arena of its own for what the body calls indirectly. Dropping it resumes the body unwinding, as `fly_handle_unwind` does today, so each frame runs its cleanups for where it stopped. A first version gives every non-direct `handle` a detached frame; nesting one whose continuation cannot leave it (`kept` false) in its enclosing frame comes after.

## Calling a machine

`R F(F_frame* fr, args...)` begins with `switch (fr->state)`, jumping to the site it stopped at; at state 0 it starts, taking its arguments. A call site of a machine:

```c
  fr->sub.s1.state = 0;
  r = G(&fr->sub.s1, a, b);              // starts G
  if (fly_pending) { fr->state = 1; return (R){ 0 }; }
  goto done1;
resume1:
  r = G(&fr->sub.s1, (A){ 0 }, (B){ 0 });   // G goes on from where it stopped
  if (fly_pending) return (R){ 0 };
done1: ;
  if (fly_unwinding) goto ...;            // as today
```

C lets `goto resume1` jump into nested blocks; nothing declared with `__attribute__((cleanup))` is jumped over, since the panic record `fr_` is declared before the `switch`. LLVM's form is a `switch` at entry over the resume blocks. A frame-resident local is reached through the frame: the C back end already maps locals to memory by macro (`withLanding`), and the frame takes the place of the C local; `defer` bodies and `handle` bodies made apart reach the enclosing function's locals by address, which in a frame are stable.

A machine called where it cannot be pending — a generator function looped over by a body that cannot suspend — is called with its frame on the caller's own stack, once.

## The runtime

- **Leaves.** A runtime routine that waits — sleeping, a socket, a channel, a contended `Mutex`, a scope's end, `join`, `Task.wait` — takes a small wait record in its caller's frame. Called first, it makes its request (what `ask` makes today) and, unless it is answered at once, marks the context pending; called again, it returns the answer. A wait that takes several steps, such as a read that may find nothing ready, keeps its step in the record.
- **Tasks.** A task is its root frame and its record. `fly_core_run(id, …)`, which today switches to the task's fiber until it asks again or ends, calls the task's root machine until it returns pending or done: the contract the scheduler in `rt/sched.fly` already has, so the scheduler does not change. Workers on every core do the same.
- **Handlers.** `fly_perform` for a handler that is not direct records the operation and marks the context pending; the body's frames return up to the `handle`'s own code (`hrun`), which runs the arm. `k(a)` puts the result where the operation reads it and resumes the body. A suspension the `handle` does not take leaves `hrun` pending, and the `handle`'s site is a site of the function it is in.
- **Generators.** `generate(f)` owns the producer's detached frame; a yield to it marks the context pending with the item; `next()` resumes the producer and takes the item, or sees it end. A producer that performs `Io` leaves `next()` pending, and the suspension goes on to the task's root.
- **WebAssembly** needs no stack switching: a program waiting for the host returns to it, and the host calls back in as the event comes. **Freestanding** programs lose nothing: their handlers and generators were fibers from `fly_os_alloc`, and are frames now.

## Phases

Each phase lands with both native back ends, C and LLVM, and every test green.

- **A. Handlers and generators as machines** (done, 0.124). `Perform`, `Resume`, yields to a `Gen`, and non-direct `handle`s become sites; `Io` still waits on the task's fiber as today. What makes a function a machine is then only what reaches a handler or a `Gen`. Fibers remain for tasks only.
- **B. Tasks as machines** (done, 0.125). `Io`'s waits become leaves; tasks, the scheduler's runs and the workers' loops call root machines. Fibers, their stacks and the stack-switching assembly are deleted.
- **C. Small frames** (done, 0.126). Liveness, overlapping fields and nested frames; the inline fast paths of an uncontended lock, a buffered read and a waiting message, and nesting the frames of `handle`s whose continuations cannot leave them, are left for later.
- **D. Measured.** A parked connection handler against the equivalent Rust future, size for size; a million parked tasks against a million futures; and the suite's benchmarks, none slower.

## Phase A as built

- Every function value — a closure, a function as a value — takes `(env, slot, yo, args…)`: the slot its frame is kept in, should it be a machine, and where its yields go, should it be a generator, whatever its static type says, since a pure function may be used where an effectful one is wanted. A machine takes its frame from the slot, pushing it on the task's frame arena as it first starts, and pops it as it ends; the frame's fields are the locals declared in a block around a point it may stop at.
- Every nesting of frames is through the arena for now: nesting a callee's frame in its caller's comes with phase C.
- A generator is a machine whose yield puts the item where its caller wants it and stops it. A loop over a generator call keeps the generator's slot in a local the back end makes (`LocalKind::Machine`), whose drop unwinds a generator left suspended, on every way out, a panic included.
- A `handle` that is not direct keeps its body's frame in its own frame, with an arena of its own for what the body calls, so a continuation outlives the code that started it. Its run code, its arms, and its continuations' resumption are machines when the code around is one.
- A `defer` cannot yet suspend: a `defer` that performs an operation of a handler that is not direct panics (`nopend`). Phase B makes cleanup a point a machine may stop at, which `Io` in a `defer` needs.

## Phase B as built

- **Leaves.** A runtime routine that waits takes a `fly_wait` record — a step and a few words — in its caller's frame, zeroed as the call starts; inside, `W_BEGIN`, `W_SUSPEND` and `W_END` make it a switch over its steps, and what it needs between them is in the record. What it was given to write to is written only as it ends, so a caller whose temporaries do not live in its frame loses nothing. A moved argument is moved once, into the frame, before the first call. In the compiled code a routine's call is marked by a byte no literal of the program's holds (`WAIT`), which the back end replaces with the record's address.
- **Tasks.** A task's entry takes the slot of its root machine's frame; the simulated scheduler's `fly_core_run` and a worker's `run_task` call it under a catch point until it ends or returns pending. Against a simulated world the tasks share one context, so what lasts while a task waits — the panic its cleanup runs for, how deep in destructors it is — is kept in its record.
- **`defer`.** A `defer` whose body may stop is a machine, called with a slot; each of its block's ways out calls it as a site, its environment, its slot and the unwinding it set aside kept in the frame, once for every way out. Such a block's locals, and those of every block around it, live in the frame.
- **Panics.** A machine whose blocks hold a `defer` that may stop catches a panic as it reaches it, and unwinds on by the flag (`fly_panic_flag`: the context's `unwinding` and `panicking`), from the block the panic was in, each block's cleanups run as code that may stop, with the direct handlers around that block. Through C the catch is a `setjmp` record the machine keeps as it starts and gives up on every way out; every local of such a machine lives in its frame, and the block it is in is written through a volatile access, since `longjmp` may restore registers that held either; the machine's own landing code does nothing when the panic is to be taken up by its record, which the unwinder reaches only past the machine's frame. Through LLVM the machine's landing pads catch. A catch point that returns with the flag takes the panic up (`fly_try_flagged`); runtime code and library routines returned to with it raise it again natively (`fly_panic_again_if`).
- **Arenas.** A generator's and a `handle`'s own arena keeps the arena it was entered from, which is in use again should it be freed while still in use, as a panic leaves it; a catch point puts the arena back where it was as it was entered, freeing what the panic left above.

## Phase C as built

- **Liveness** (frames.fly `residents`). A local is in the frame if it is live across a point the code may stop at: found backward, a whole definition killing it, loops gone round to a fixpoint, `break`, `continue` and a `catch` given what is live where they go. A point's own operands count only for `Gen_next`, which reads its generator's place again: a call is given nothing to go on with, and a routine that waits copies what it is given to the frame as it starts. Two kinds of local stay in the frame whenever they are in scope at a point, live or not: what a block's cleanup reads, which the code zeroes as the block begins, before any point it goes on from; and a local whose address is taken, which may be read through the address. On the compiler, 37% fewer frame fields.
- **What one point keeps** (`transient`): a wait record, a callee's slot, arguments moved to a routine, a function value being called, a result written after the call, are dead before the next point begins, so each point's are a group of the frame's union `t`, the groups overlapping. Storage that lives across several points — a `defer`'s, `Io.scope`'s, a loop over a generator's, a direct `handle`'s — stays apart.
- **Nesting**. A direct call of a machine marks where its frame would go, as the last member of its point's group, and the slot's first value. Once the program is put together, a call nests unless its callee may call the caller again (`reaches`, over every call the code makes, code apart included); the frame types are emitted after the frames nested in them, and through LLVM each frame's size, with what nests in it, is worked out callee first. A nested frame's slot holds its address with the low bit set: the callee takes it as its frame, and neither takes it from the arena nor gives it back.
- **Arenas and tasks.** An arena's first chunk is the size of its first frame, each next twice the last up to 16 KB, and one emptied chunk is kept for the next; a task that stops gives that back, so it holds only the frames it is in. A threaded task's record is 248 bytes: its closure is in it, it allocates no result it does not give, and of the context it keeps only what lasts while it waits.
- **The scheduler.** Each worker sleeps on a condition of its own, woken by whoever has work for it, and keeps a timer of its own, which any worker fires once it is due.
- **Measured** (`bench/tasks.sh`, an M5 Ultra, against Rust on tokio): a million tasks each parked on a timer take 413 MB, tokio's 256; parked two calls deep, in a handler and the helper it waits in, 509 MB to tokio's 501, and in 0.4 seconds of the kernel's time to tokio's 8.8. What the bare task takes beyond tokio's is its record, its scope's list and its timer's entry, which a task of tokio's keeps in its future.
