# Step 15: suspending code as state machines — the implementation

The roadmap's step 15 says what is wanted: a parked task holds what a Rust future holds, and fibers are gone from the native runtime. The review of 2026-10-24 (`2026-10-24-panics-and-state-machines.md`) settled the shape: frames of direct calls nest in their caller's, frames of indirect and recursive calls come from a task's frame arena, and a continuation that outlives its `handle`, or a `Gen`, owns a detached arena. This document says how the compiler and the runtime do it, and in what order, each phase leaving every test green on every back end.

## One protocol for every suspension

Today three things suspend, each its own way: a task asks the scheduler by switching to its fiber (`ask` in runtime.c); a body under a handler that is not direct performs by switching to the handler's fiber; a producer under `generate` yields by switching back to `next()`. After this step all three are one thing: **a call returns with the task's context marked pending**, and everything between the code that suspended and the code that takes the suspension returns too, each function having saved where it was.

- `fly_pending` is a field of the task's context, as `fly_unwinding` is. A function that can suspend checks it after each call that can, exactly where it checks `fly_unwinding` today.
- What the suspension is for is in the context too: a request to the scheduler (what `ask` passes today), an operation performed for handler `h`, or an item yielded to a `Gen`. Whoever takes it clears `fly_pending`.
- Resuming calls the same functions again, from the root of what suspended: each finds where it stopped in its frame and goes on.

## Which functions are state machines

A C function the back end emits — a function instance, a closure, or code made apart: a `handle`'s body or arms, a loop's body over a generator, a `defer` — is a **machine** if it contains a suspension site, a statement that may leave it pending:

- a call whose IR `suspends` flag is set (in phase B, when `Io` suspends) and every call of a machine, directly or through a function value whose type can suspend;
- `Perform`, `Resume`, and a `Yield` that goes to a sink that may suspend;
- a `handle` that is not direct, whose body or arms may leave pending what the `handle` does not take.

Everything else is compiled as it is today, and runs on the worker's own stack wherever it is called from. A function that cannot suspend costs nothing new.

## Frames

A machine `F` has a frame, a C struct (and the same layout in LLVM):

```c
typedef struct F_frame {
  uint32_t state;              // 0 before it starts; otherwise the site it stopped at
  T3 v3; T7 v7; ...            // the locals live across a site
  union {                      // the frame of the call it is in, at one site at a time
    G_frame s1; H_frame s2; void* s4;
  } sub;
} F_frame;
```

- **Which locals.** A local is in the frame if it is in scope at some site and the code may read it after that site: a use after the site in the local's scope (anywhere in a loop around the site, which may run again), or a cleanup of its block — a drop, an arena, a `defer`'s flag — which runs as the block is left. The rest stay C locals, dead across every site. A first version keeps one field per such local; overlapping fields whose lifetimes are disjoint (a union per group of sites) comes after, measured.
- **Nested frames.** A direct call of a machine that is not in the caller's strongly connected component nests the callee's frame in the caller's `sub` union. A task whose calls are all of that kind has one frame of a size the C compiler knows.
- **Arena frames.** A call through a function value, or within a cycle of machines, takes its callee's frame from the task's frame arena (`fly_frame_push(size)`, popped as the call ends), and keeps the pointer in `sub`. A function value whose type can suspend carries its frame size. Arena chunks never move, so a borrow into a frame stays good while it is suspended.
- **Detached frames.** A `handle` that is not direct, and `generate`, own their body's frame: a heap frame, as a `handle`'s is today, with a frame arena of its own for what the body calls indirectly. Dropping it resumes the body unwinding, as `fly_handle_unwind` does today, so each frame runs its cleanups for where it stopped. A first version gives every non-direct `handle` a detached frame; nesting one whose continuation cannot leave it (`kept` false) in its enclosing frame comes after.

## Calling a machine

`R F(F_frame* fr, args...)` begins with `switch (fr->state)`, jumping to the site it stopped at; at state 0 it starts, taking its arguments. A call site of a machine:

```c
  fr->sub.s1.state = 0;
  r = G(&fr->sub.s1, a, b);              // starts G
  if (fly_pending) { fr->state = 1; return (R){ 0 }; }
  goto done1;
resume1:
  r = G(&fr->sub.s1, (A){ 0 }, (B){ 0 });   // G goes on from where it stopped
  if (fly_pending) return (R){ 0 };
done1: ;
  if (fly_unwinding) goto ...;            // as today
```

C lets `goto resume1` jump into nested blocks; nothing declared with `__attribute__((cleanup))` is jumped over, since the panic record `fr_` is declared before the `switch`. LLVM's form is a `switch` at entry over the resume blocks. A frame-resident local is reached through the frame: the C back end already maps locals to memory by macro (`withLanding`), and the frame takes the place of the C local; `defer` bodies and `handle` bodies made apart reach the enclosing function's locals by address, which in a frame are stable.

A machine called where it cannot be pending — a generator function looped over by a body that cannot suspend — is called with its frame on the caller's own stack, once.

## The runtime

- **Leaves.** A runtime routine that waits — sleeping, a socket, a channel, a contended `Mutex`, a scope's end, `join`, `Task.wait` — takes a small wait record in its caller's frame. Called first, it makes its request (what `ask` makes today) and, unless it is answered at once, marks the context pending; called again, it returns the answer. A wait that takes several steps, such as a read that may find nothing ready, keeps its step in the record.
- **Tasks.** A task is its root frame and its record. `fly_core_run(id, …)`, which today switches to the task's fiber until it asks again or ends, calls the task's root machine until it returns pending or done: the contract the scheduler in `rt/sched.fly` already has, so the scheduler does not change. Workers on every core do the same.
- **Handlers.** `fly_perform` for a handler that is not direct records the operation and marks the context pending; the body's frames return up to the `handle`'s own code (`hrun`), which runs the arm. `k(a)` puts the result where the operation reads it and resumes the body. A suspension the `handle` does not take leaves `hrun` pending, and the `handle`'s site is a site of the function it is in.
- **Generators.** `generate(f)` owns the producer's detached frame; a yield to it marks the context pending with the item; `next()` resumes the producer and takes the item, or sees it end. A producer that performs `Io` leaves `next()` pending, and the suspension goes on to the task's root.
- **WebAssembly** needs no stack switching: a program waiting for the host returns to it, and the host calls back in as the event comes. **Freestanding** programs lose nothing: their handlers and generators were fibers from `fly_os_alloc`, and are frames now.

## Phases

Each phase lands with both native back ends, C and LLVM, and every test green.

- **A. Handlers and generators as machines.** `Perform`, `Resume`, yields to a `Gen`, and non-direct `handle`s become sites; `Io` still waits on the task's fiber as today. What makes a function a machine is then only what reaches a handler or a `Gen`. Fibers remain for tasks only.
- **B. Tasks as machines.** `Io`'s waits become leaves; tasks, the scheduler's runs and the workers' loops call root machines. Fibers, their stacks and the stack-switching assembly are deleted.
- **C. Small frames.** Overlapping fields, nesting the frames of `handle`s whose continuations cannot leave them, and the inline fast paths of an uncontended lock, a buffered read and a waiting message.
- **D. Measured.** A parked connection handler against the equivalent Rust future, size for size; a million parked tasks against a million futures; and the suite's benchmarks, none slower.
